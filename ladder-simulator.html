Ladder Logic Simulator

A self-directed learning project: a browser-based simulator that models how a real PLC (Programmable Logic Controller) evaluates ladder logic, built to translate the fault-interlock state machine from my Raspberry Pi Pico trainer into industry-standard ladder notation.

Instruction symbols and layout follow Allen-Bradley/RSLogix conventions (XIC, XIO, OTE), the North American industry standard, since that's the convention most relevant to the equipment I'd be working with in a maintenance role.

What this is: a learning tool I built to understand ladder logic concepts, not a certified, IEC 61131-3-compliant, or production PLC programming environment.

Starts the line, trips a fault, and resets it automatically — no clicking required.

How each rung maps to the Pico trainer

Rung 1 — Fault latch

The Jam contact sets the Fault coil, and a seal-in contact (Fault, in parallel with Jam) keeps it energized on its own even after Jam clears, exactly like the Pico's fault-interlock logic stayed latched in the Fault state until told otherwise. Only Reset breaks the seal. This is the same behavior as the Pico's state = "Fault" holding until the reset switch was read.

if jam or fault: fault = True and not reset

Rung 2 — Start/Stop seal-in with fault interlock

This is the classic motor-starter circuit: Start energizes Run, a seal-in contact (Run) keeps it energized after Start is released, and Stop breaks the seal. The Fault contact in series gates the whole rung off the moment Fault is set, the same lockout the Pico enforced by disabling its Start/Stop switch reads whenever state == "Fault".

if (start or run) and not stop and not fault: run = True else: run = False

Rung 3 — Motor output

A direct output: Run energizes the Motor coil, mirroring the Pico's status LEDs turning on when it entered the Running state.

motor = run

What's simplified here

The Pico trainer requires holding the Jam switch for 2 seconds before it counts as a fault (debounce), so a quick bump doesn't trip it. A real PLC would do that with a timer instruction (TON). Left out here on purpose to keep the diagram focused on scan-cycle behavior and NO/NC contact logic, the two core concepts this project is built to demonstrate.
